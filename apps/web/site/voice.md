## 这个站怎么写

**读者是谁**：macOS 上的开发者，多半正卡在一个具体故障里。他已经有一套代理方案在跑
（Clash / Surge / xray 之类），系统代理也设了，但某个软件当没看见。他搜的是自己的
故障，不是我们的产品名。

可以默认他已经知道的：什么是 HTTP/SOCKS 代理、什么是环境变量、怎么用 curl 和
`lsof`、终端不怕。**不要**从"什么是代理"讲起。

不能默认他知道的：macOS 的 Network Extension 是什么、透明代理和 TUN 的区别、
为什么系统代理设置对某些程序完全无效。这三件事恰好是我们要反复讲清的。

**结论放最前面。** 第一段就说清"为什么会这样"和"怎么办"，然后再展开机制。他是来
解决问题的，不是来读教程的——铺垫、学习目标、章节导航一律不要。

**什么算证据**：一手经历、可复现的命令与输出、源码或官方文档。不算证据的：听说、
推测、"通常来说"。**没验证过就不要写成事实**——写"我们没测过 X"比编一个结论好，
读者会因为这句话更信你其余的部分。

**说清代价。** 每个方案都有不适用的场景。"什么时候不该用这个方法"和"怎么用"一样
重要，而且更少有人写。

### 绝对不写

1. **不把 Appidge 说成它不是的东西。** 它不是 VPN、不是机场客户端、不是代理切换器，
   **不提供任何节点**——出口永远是读者自己配置的上游。"提供节点/内置节点/自带节点"
   这类说法在产物里被 `check-blog.mjs --redline` 硬拦。
   说"不是 VPN"是可以的，而且应该说，那是澄清。
2. **不写独立单词 `mock`。** 官网的 `check-site.mjs` 第 6 条对整个 `dist/` 扫
   `\bmock\b`，一旦命中，**官网测试直接变红**。写"打桩""替身""假数据"。
   同理不写 `PLACEHOLDER`，不写 `api.appidge.com`（私有 API 地址不进营销站产物）。
3. **不编造产品行为和参数。** 事实基准是 appidge 的实际实现：全接管进程网络、
   按进程+目的地分流、较新的同类规则覆盖旧的、活动页点进程当场改规则、
   自动放行本地代理自身流量防转发环、检测到他方 TUN 虚拟网卡时警示冲突。
   拿不准就去读源码或不写。
4. 不写竞品的坏话。讲边界和取舍，不讲优劣。

### 改写对照

抽象的语气描述人人理解不同，一对具体的改写没有歧义。

✗ 在本文中，我们将深入探讨 macOS 网络代理的核心概念。首先，让我们一起了解什么是
代理；其次，我们会全面解析透明代理的原理；最后，通过本文你将能够掌握最佳实践。

✓ Docker Desktop 拉镜像不走你的代理，是因为拉取动作发生在它自己的虚拟机里，那个
进程读不到你 macOS 上的任何代理设置。三种解法，代价依次递增：给 Docker 单独配
代理（最快，但只管 Docker）、按进程接管（管所有这类程序）、上 TUN（全都管，但要
改路由表，崩了整机断网）。

差在哪：前者三段全是铺垫，读完不知道任何事；后者第一句给结论，第二句给机制，
第三句给带代价的选项。

## 怎么改这份文件

frontmatter 里的 `signals` 是给 `pnpm analyze` 读的——它只能识别机械痕迹：套话、
名词罗列、缺少第一手经验。上面的正文是给 agent 读的。

两者是分工，不是重复：短语表永远判断不了「这段话有没有信息量」，正文也永远变不成
退出码。想让某个词不再被扣分，就从 `avoid` 里删掉它；想换一种口吻，就改正文。

风格分数**不阻断发布**（`site/policy.yaml` 的 `style.minScore` 默认为 null）。
它是一个指向「这几段值得重写」的指针，不是判决。
